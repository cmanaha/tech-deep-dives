## Mental models

1. **The backend picks the page size, and the page size picks how finely prefixes are reused.** `--page-size` starts at 1. FlashInfer, FA3 and Triton keep it; TRT-LLM MHA and MLA, FlashMLA, FA4 and DSA raise it to between 32 and 128 tokens. The radix cache matches whole pages only, so moving the same Llama deployment from H100 (`fa3`, page 1) to B200 (`trtllm_mha`, page 64) changes prefix reuse from token-exact to 64-token steps, and a prompt shorter than one page is never cached. Rows B13, B14, A4, A7, A16; register 02 B6, B14.
2. **The default is decided by model family first, GPU generation second.** Platform hooks run, then 33 per-architecture override modules (DeepSeek V3 family to `trtllm_mla` on SM100, DSA models to `dsa`, DeepSeek V4 to `dsv4`, Qwen3.5 hybrids to `triton` or `trtllm_mha`, GPT-OSS by its own rule), and only a model with no rule reaches the generic GPU table. To predict the backend for a new model, look for its override module before reading the table. Rows A3, A4, A6, A7, A8, A11, A12, A14, A18.
3. **Most backend names are routes to an upstream kernel project, each with its own pin.** TRT-LLM kernels arrive through FlashInfer 0.7.1; FA3 and FlashMLA through the `sglang-kernel` 0.4.9 wheel built from SGLang forks; FA4 is vendored in-tree; DeepGEMM comes from the `sgl-deep-gemm` 0.2.2 fork. An upstream fix reaches a deployment when that pin moves, which is why the same kernel can behave differently in SGLang and vLLM at the same calendar date. Rows B1, B2, B5, B6, B7, B9, C1, C2, C6, G5.
4. **The checkpoint decides the quantization format; `--quantization` is for online quantization or a declared compatible override.** A mismatched flag fails at startup, a BF16 checkpoint with `--quantization fp8` is quantized at load, the loader refuses GPUs below the format's minimum capability, and FP8 on Ampere runs weight-only through Marlin. Rows D2, D3, D4, D5, D6, D10.
5. **Kernel compilation is part of startup unless you move it to build time.** DeepGEMM compiles every M for each new GEMM shape on the first rank of each node, tvm-ffi JIT kernels build on first use, and all of it lands in on-host caches. `python -m sglang.compile_deep_gemm` plus a persistent cache volume turns a slow first start into a fast one. Rows C4, C8, C9, C10, C12.

## Where SGLang differs from vLLM

Design differences only. Each names the vLLM dive section that covers the vLLM side.

- **How the default is chosen (G1).** SGLang uses an ordered rule chain with per-model override modules and silent page-size rewrites. vLLM walks a per-GPU priority list in which each candidate validates the configuration. vLLM side: "14. Inside the Codebase", tab "Execution & Attention".
- **What can be split (G2).** SGLang splits kernels by phase (prefill versus decode). vLLM's override splits by KV-cache group kind. vLLM side: "14. Inside the Codebase", tab "Execution & Attention".
- **Default kernels (G3).** Hopper dense models run FlashAttention 3 in both engines. On B200, SGLang defaults to TRT-LLM-gen kernels through FlashInfer with 64-token pages. vLLM side: "14. Inside the Codebase", tab "Execution & Attention".
- **Kernel packaging (G4, G5).**
  - SGLang ships a separate `sglang-kernel` wheel plus host-side JIT, and takes FA3, FlashMLA and DeepGEMM from its own forks.
  - vLLM compiles `csrc/` into its own extension.
  - vLLM still has CUTLASS MLA; SGLang removed it.
  - vLLM side: "14. Inside the Codebase", tab "Architecture & Module Map", and the "Execution & Attention" tab.
- **Page granularity (G6).** SGLang starts at 1-token pages and raises them per backend; vLLM starts at 16-token blocks. vLLM side: "5. Paged KV Cache & Block Tables".
- **Quantization flags and formats (G7, G8, G9).**
  - SGLang keeps plain `--quantization fp8` for online FP8, where vLLM v0.31.0 has moved to scheme names.
  - Both rank DeepGEMM first for block FP8.
  - SGLang's KV dtypes add MXFP8 and two FP4 recipes but no integer KV.
  - vLLM side: "8. Quantization & Precision".
- **AWS accelerators (G10).** Both engines reach Trainium through an out-of-tree plugin. vLLM's plugin has releases. SGLang's plugin was not located in this research, and no Neuron code was found in the v0.5.22 tree (F7). vLLM side: "21. vLLM on AWS Neuron".
