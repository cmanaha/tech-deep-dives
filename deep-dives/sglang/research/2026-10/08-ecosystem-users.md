Rule for this register: a production-use claim is recorded as fact only from a FIRST-PARTY statement
(the company that runs SGLang says so on its own channel), or an SGLang/LMSYS statement that names the
company and links to that company's own statement. Logo walls and "used by" lists are project claims

## Mental models

1. **SGLang is a runtime plus a family of projects around it.** One Python package (`sglang`) carries the LLM runtime and SGLang Diffusion; audio (SGLang Omni), draft-model training (SpecForge), TPU engines (SGL-JAX, SGLang-TorchTPU), the gateway (SMG), Kubernetes APIs (RBG, OME) and NPU/XPU kernels each ship from their own repository on their own release train. Predicts: a feature announced for "SGLang" may need a second package and a second version pin. Rows B1-B8, D5, C8.
2. **Every downstream pins its own SGLang, and the gap is the thing to check.** RL frameworks, orchestrators and vendor containers each freeze a version: Miles and llm-d track v0.5.22, Dynamo 0.5.21, NVIDIA NGC 0.5.19, slime 0.5.15.post1, AReaL 0.5.10.post1, verl 0.5.8, ROLL 0.5.2. Predicts: the SGLang you run under a framework is usually older than the docs you read, and may lack the latest security fixes. Rows B9-B15, D2, E8, register 06 F13.
3. **Adoption evidence comes in four strengths.** Project logo walls and scale numbers (C1, C2, C20, C21) < claims by RadixArk, which commercialises SGLang (C2) < vendors offering SGLang as a product option (C8, C9, C11, D2-D7, register 09) < a company saying it runs its own product on SGLang (C3 LinkedIn, C4 Cloudflare, C5 Baseten, C10 Novita). Predicts: a named user is only as solid as the rung its source sits on. Row C19.
4. **SGLang's attack surface is its internal sockets and Python deserialization, not its HTTP API.** Defaults bind 127.0.0.1 and leave dangerous features off; the 2026 critical CVEs all arrive when an unauthenticated pickle/dill path becomes reachable, usually through `--host 0.0.0.0` or an opt-in flag. Predicts: the safe pattern is loopback or a private network behind a gateway, plus API keys. Rows E2-E6.
5. **An LMSYS-hosted project with a commercial maintainer next to it.** LMSYS (a non-profit) hosts SGLang; RadixArk, founded around the project, is "a maintainer" and builds a paid platform on SGLang and Miles. vLLM is hosted by the PyTorch Foundation. Rows A4, A5, A14.

## Section recommendation

- **"SGLang in the wild: the project, its family and who runs it"** (depth: overview, with one practical table). Open with mental model 1 and diagram 1: SGLang is one package plus a family of separately released projects, hosted by LMSYS with RadixArk as a commercial maintainer. Then the evidence ladder (diagram 2) with the four strengths of adoption evidence, leading with LinkedIn's ranking stack (C3: multi-item scoring cut 50-item ranking latency 69%, LinkedIn's measurement) and Cloudflare's move of Clef to SGLang (C4). Put logo walls and scale numbers in an attributed note. End on the reader's action: check which SGLang version your framework or vendor container pins (diagram 3, B15).
- **"Before you expose it: SGLang's security posture"** (depth: practical; could be a block inside an operations section). Open with the strongest number: nine CVEs in 2026, five critical, all through deserialization or uploads (E2). Then the defaults that protect you (loopback bind, custom logit processor off) and the ones that do not (no API key by default, ADMIN_OPTIONAL endpoints open without keys) (E4-E6). End on the action: run v0.5.22 or later, keep `--host` private or behind a gateway, set `--api-key` and `--admin-api-key`, and watch the GitHub Advisory Database because the repo has no security policy (E1, E3).
