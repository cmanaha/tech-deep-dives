## Mental models

1. **Same engine class, different defaults at the edges.** Paged KV, default-on prefix caching, default-on CPU/GPU overlap, FCFS queues, recompute-on-preemption, FlashAttention 3 on Hopper and FlashInfer on Blackwell are common to both; the differences sit in how the prefix index is shaped, how fine the reuse unit is, and what ships in the same repo (router, PD control plane, admin APIs). Predicts: a feature-list comparison mostly finds parity; a configuration comparison finds the differences. (A2 to A4, A10, B1 to B4)
2. **A tree with variable-length edges versus a chain of fixed-size block hashes.** SGLang's lookup returns the longest cached token run and evicts whole leaves; vLLM's returns the longest run of full blocks and evicts block by block. Predicts: on Hopper SGLang reuses the last up-to-15 tokens vLLM recomputes; on B200 at defaults the comparison flips (64-token pages versus 16-token blocks). (A6, A7, 02-G1, 02-G2)
3. **SGLang puts the fleet pieces in the engine project; vLLM puts them beside it.** Router, PD pairing, bootstrap server and RL admin routes ship with SGLang and are on or available by default; vLLM leaves them to connectors, proxies, production-stack, llm-d or Dynamo, or behind a dev-mode switch. Predicts where an operator finds a knob, and why SGLang needs `--admin-api-key` in production. (A14, A15, A19, B6)
4. **The two codebases share kernels and code; benchmark gaps come from versions and settings.** Both pin FlashInfer 0.7.x, build FlashAttention from forks, and carry code adapted from each other. Predicts: a head-to-head result tracks release dates and matched flags more than engine identity. (B4, B5, C)
