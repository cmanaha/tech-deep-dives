## Mental models

1. **A grammar is a CPU state machine that writes a vocabulary bitmask before every sample.** Everything practical follows: compilation is a one-off cost per distinct schema string (A7, A8), the mask is applied after penalties and before `logit_bias` (A10), and with overlap on, only the sampling kernel waits for the CPU (A11). Rows A7 to A11, B5.
2. **Speculative decoding is "draft cheaply, verify once, keep the agreed prefix plus one".** One verify forward scores every drafted token; the accepted prefix plus the target's own bonus token is committed, then the draft catches up (draft-extend). A tree (top-k above 1) spends more verify width to raise the accepted length; a chain spends none. Rows C4 to C6, C14, E7.
3. **The two features compose by masking the draft tree.** Under a grammar, each draft-tree node gets its own mask row from a CPU walk of the tree, so the target can only accept grammar-legal drafts, and a grammar that finishes mid-run truncates the accepted tokens. Rows D4 to D6.
4. **Speculation trades concurrency for single-stream speed.** Turning it on resets `--max-running-requests` to 48, the verify graphs get wider, and adaptive mode turns drafting off from 64 concurrent requests by default. Rows C9, C10, D7, F6.
5. **SGLang settles flags in resolution hooks, and the docs lag them.** Many speculative defaults are `None` in the field and decided in `arg_groups/speculative_hook.py`; several documented restrictions (NGRAM and DFLASH disabling overlap, overlap requiring top-k 1, NGRAM being CUDA-only) do not match the hooks at v0.5.22. Rows C4, C11, D2, D3.

## Where SGLang differs from vLLM (design choices)

- Default grammar backend: SGLang fixes XGrammar and rejects schemas it cannot enforce; vLLM's default `auto` falls back per request to guidance. vLLM side: "12. The OpenAI-Compatible Server". Rows F1, B2.
- Request surface: SGLang takes `regex`/`ebnf` as top-level extra fields and `structural_tag` as a `response_format` type; vLLM nests constraints under `structured_outputs` and adds `choice`. vLLM side: "12. The OpenAI-Compatible Server". Row F3.
- Tree drafting: SGLang's EAGLE drafts trees and auto-selects one for Llama targets; vLLM 0.31.0 verifies K-token chains (no token-tree option found). vLLM side: "11. Speculative Decoding". Row F4.
- Batch-size adaptation: SGLang adapts steps from the observed accept length per batch-size band; vLLM maps batch-size ranges to a fixed K. vLLM side: "11. Speculative Decoding". Row F6.
- Scheduler coupling: every SGLang built-in algorithm runs under the overlap scheduler on GPU; vLLM disables async scheduling for unsupported speculative methods. vLLM side: "4. Scheduler & Continuous Batching" and "11. Speculative Decoding". Row F7.
- Grammar plus speculation: SGLang masks the draft tree node by node and overlaps that CPU work with verify for GPU drafters. The vLLM side of this interaction was not researched here.
