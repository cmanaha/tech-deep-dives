## Mental models

1. **One TP group, carved three ways.** An SGLang server is `tp_size x pp_size` GPUs. Inside each TP group, attention is split by attention DP (different requests), attention CP or DCP (different tokens of one request) and attention TP (different heads); the MoE layers reuse the same GPUs split by EP (different experts) and MoE TP. Predicts: `--tp 8 --attn-dp-size 8 --ep 8` is 8 GPUs, not 64; `--dp-size` is the only flag that adds GPUs by copying the model. Rows A1, A3, A4, B2, B3, F4.
2. **MLA KV is per token, not per head, so TP copies it and DP attention divides it.** Under plain TP every rank holds the same latent KV; attention DP turns N copies of one batch into N different batches. Predicts: DP attention raises batch capacity for DeepSeek-class models and does little for GQA models whose KV heads TP already splits. Rows A9, A10, F7.
3. **The EP group moves in lockstep.** All-to-all is a collective, so every rank must pick the same DeepEP mode and the same graph decision each step: one rank prefilling forces normal mode and no decode CUDA graph on all of them. Predicts: colocated DP attention + DeepEP alternates modes under mixed load, and PD disaggregation is what keeps prefill on normal and decode on low-latency. Rows B6, B7, B8, B21.
4. **PD is a rendezvous on a room id, then a push.** The router stamps one random `bootstrap_room` on two simultaneous requests; decode looks up prefill's ranks in the prefill's bootstrap registry, reserves pages, publishes their addresses, and prefill RDMA-writes KV into them chunk by chunk. Predicts: decode capacity throttles prefill admission under the default `early` policy; a lost prefill node fails its rooms on decode after about two heartbeats. Rows C4, C6, C8, C9, C14, C17.
5. **EFA is a protocol switch, not a new backend.** The same Mooncake code runs over EFA with `MOONCAKE_PROTOCOL=efa` and the EFA wheel, as libfabric RDM writes of GPU memory; the price is no CUDA VMM allocators and no Mooncake EP. Rows D1-D6.

## Where SGLang differs from vLLM

- **Attention DP is a width inside TP, not a replica count.** SGLang `--tp 8 --attn-dp-size 8` vs vLLM `-dp 8` with EP (vLLM section "9. Distributed Inference"). Rows F4, A3, A4.
- **EP width is tied to TP whenever an all-to-all backend is on** (`ep_size = tp_size`); vLLM sets EP = TP x DP (section 9). Rows B2, F4.
- **PD is a scheduler mode with a built-in bootstrap registry**, not a connector plugin plus proxy (vLLM section "10. Disaggregated Prefill / Decode"). Rows F2, C4.
- **Push only.** SGLang's Mooncake and NIXL backends both RDMA-write from prefill; vLLM's default NIXL connector pulls (section 10, section "22. vLLM on AWS GPUs, EFA & NIXL"). Rows F1, C14.
- **Both legs dispatched at once** by the gateway; vLLM's pull-mode proxy runs prefill first (section 10). Row F3.
- **EFA route**: SGLang documents Mooncake over EFA; the AWS-documented and vLLM-dive route is NIXL LIBFABRIC, which SGLang also accepts by env var (section 22). Rows F6, D1-D10.
- Shared ideas: both have DCP for MLA (F7), both have a Mooncake path with a bootstrap port 8998 (F1), both have EPLB.
