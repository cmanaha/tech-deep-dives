## Findings

**1. BLOCKER.** The vocabulary of the dive's headline question is never defined. Thesis: "shard model state across data-parallel ranks"; section 8 (Data parallelism and sharding): "a sharding factor F between 1 (DDP) and the world size"; section 13 (Composing the dimensions): "Megatron-Core: default rank order "tp-cp-ep-dp-pp", with adjacent ranks expected to share a node" and "composed on one device mesh"; section 14 (Set my ranks: the sizing procedure and calculator): "satisfy the divisibility constraints of both grids"; section 27 (Trainium): "A rank is a logical NeuronCore".
- *Problem:* The brief's deliverable is "help me set my ranks and parallelization". Outside the Trainium-specific line in section 27, the scope never says what a rank is, what the world size is, what a parallelism's degree is, that the degrees of a layout multiply to the world size, that each rank therefore holds a coordinate on a grid (the device mesh), or how rank numbers land on instances. Every layout in the dive is written in that notation from the thesis on ("TP 8 x PP 4 x DP 8"), and section 13's rule "nest innermost-fastest, TP then CP then PP then DP, with the innermost inside one instance" only makes sense once the reader knows that consecutive ranks share an instance. The identity exists in the register (02 section 3.5, the assembled procedure, step 8: "World size = TP x CP x PP x DP for the dense grid and ETP x EP x EDP x PP for the expert grid") but section 14 compresses it to "satisfy the divisibility constraints of both grids". Section 2's four prerequisite concepts omit it and section 32's glossary does not list rank, world size, degree or device mesh. "Knows NCCL by name", the stated background, does not supply this model.
- *Fix:* (a) Open section 7 (Collectives), which already "introduces the vocabulary every later section uses", with: "A rank is one training process; on GPUs one rank drives one GPU, and the world size is the number of ranks in the job. Each parallelism has a degree, the number of ranks it splits across, and the degrees multiply to the world size: TP 8 x PP 4 x DP 8 is 256 ranks, or 32 p5.48xlarge. Each rank therefore holds a coordinate on a grid, which PyTorch calls a device mesh. Megatron Core expects consecutive ranks to share an instance (T02-51), so the grid's innermost dimension is the one that stays on NVLink." The general claim about launcher numbering beyond Megatron Core needs a register entry in wave 2. (b) Restate step 8 of section 14's procedure as: "the degrees multiply to the world size (TP x CP x PP x DP for the dense layers, expert-TP x EP x expert-DP x PP for the expert layers), and each degree divides what it splits: heads by TP, layers by PP, the global batch by micro-batch x DP." (c) Fold it into section 2's prerequisite (c) so the count stays at four: "(c) Ranks and collectives: one process per accelerator, the degrees of a layout multiply to the world size, and ranks exchange data through all-reduce, reduce-scatter, all-gather, all-to-all and send/receive, priced as bytes over link bandwidth (section 7)." (d) Add rank, world size, degree, device mesh and rank order to section 32.
